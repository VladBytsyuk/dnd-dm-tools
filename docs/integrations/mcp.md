# Локальный MCP

В настольном Obsidian откройте настройки DnD DM Tools и включите **MCP**. Сервер входит в сборку плагина и работает, пока открыт Obsidian; отдельная установка не нужна. Поддерживается встроенный Node.js 20 или новее.

В блоке **«Подключение MCP»** находятся адрес `http://127.0.0.1:<порт>/mcp`, токен и пример конфигурации HTTP-клиента. Каждый запрос требует `Authorization: Bearer <токен>`. Порт и токен сохраняются между перезапусками. Занятый порт можно изменить либо выбрать свободный. Смена порта, токена или режима доступа завершает прежние сессии и отменяет ожидающие подтверждения.

**«Только чтение»** скрывает и блокирует инструменты изменения. Чтение отсутствующей полной карточки по-прежнему может загрузить её в локальный кеш. Журнал доступен в настройках даже при выключенном сервере.

## Чтение

Поддерживаются девять справочников (`bestiary`, `spellbook`, `arsenal`, `armory`, `equipment`, `artifactory`, `backgrounds`, `feats`, `races`) и четыре типа медиатеки (`adventure`, `scene`, `track`, `playlist`).

- `list_entity_types` — поддерживаемые типы и операции.
- `get_entity_schema` — полная схема, шаблон создания, `filterSchema` и `filterValues` выбранного типа.
- `search_entities` — поиск по имени и URL, `kinds`, `offset`, `limit`, необязательный `filters`. Поиск не загружает Full.
- `get_entity` — полная карточка и `revision`. Full загружается только для URL из локального справочника; произвольный внешний адрес недопустим.
- `list_audio_assets` — все известные аудиоссылки; прежний массив результатов дополнен `exists` и `registered`.
- `search_audio_assets` — поиск по имени и пути с пагинацией, по умолчанию 20, максимум 100 результатов. `id: null` означает отсутствие регистрации; `exists: false` — отсутствие файла в текущем индексе vault.

Фильтры требуют выбора одного типа, например:

```json
{"kinds":["spellbook"],"filters":{"levels":[2,3],"schools":["Воплощение"]},"limit":20}
```

Значения внутри одного поля объединяются через «ИЛИ», поля — через «И». Приключения и сцены поддерживают `campaignNames`. Точные значения следует получать через `get_entity_schema`.

Тексты заметок и содержимое аудиофайлов недоступны. Пути заметок сохраняются только как ссылки.

## Запись и подтверждение

Клиент должен поддерживать **form elicitation**. Каждое сохранение требует `accept` и явно указанного `confirm: true`. В подтверждении видны только тип, имя и действие; содержимое статблока или приключения туда не включается. Отказ, отмена, истечение пяти минут и отсутствие elicitation не меняют карточки.

- `create_entity` принимает `kind`, полную `data`, необязательный `operationId`.
- `update_entity` принимает `kind`, `url`, полную `data`, `expectedRevision`, необязательный `operationId`.
- `patch_entity` принимает `kind`, `url`, `changes`, `expectedRevision`, необязательный `operationId`. Объекты объединяются рекурсивно, массивы заменяются целиком. `null` допустим только там, где это разрешает схема; он не означает удаление поля.
- `apply_entity_batch` принимает обязательный `operationId` и 1–50 действий `create`, `update`, `patch`. Для группы показывается одно подтверждение, а сохранение выполняется целиком одной транзакцией. Повторное изменение одной записи запрещено.

Получайте свежую `revision` через `get_entity`. После подтверждения сервер проверяет её повторно. Изменение внешней карточки создаёт ручную копию с новым URL. ID и URL существующих ручных записей неизменяемы; происхождение определяет сервер.

Для музыкального трека можно указать `normalAudioPath` и/или `combatAudioPath`, например `Music/adventure_begins_loop.mp3`. Поддерживаются MP3, OGG, WAV, M4A, FLAC, AAC и OPUS. Сервер проверяет наличие файла и регистрирует ссылку вместе с подтверждённым сохранением трека. Путь заменяет соответствующий `AudioId`; чтобы убрать привязку, передайте `AudioId: null` без пути.

В группе заранее задавайте ID новых медиасущностей: сначала трек, затем плейлист со ссылкой на него, затем сцены и приключение. Ссылки допускаются на уже существующие записи и предыдущие действия группы. Лимит HTTP-запроса — 1 МиБ.

## Повторы, история и откат

Для восстановления после потери ответа **заранее задавайте уникальный `operationId`**: 1–128 латинских букв, цифр, `_` или `-`. Если клиент не передал ID одиночной операции, его создаст сервер; заранее узнать его для повтора будет невозможно.

- `get_operation(operationId, includeChanges?)` возвращает статус и сохранённый результат; `includeChanges: true` добавляет снимки «до/после».
- `list_operations(offset?, limit?)` возвращает журнал с кратким списком сущностей, без полных снимков.
- `undo_operation(operationId, targetOperationId)` создаёт отдельную операцию отката с новым подтверждением.

Статусы: `pending`, `running`, `succeeded`, `rejected`, `failed`, `interrupted`. Причина отказа или ошибки возвращается как `{code,message}`. Повтор успешного запроса с тем же ID и содержимым возвращает прежний результат без повторного сохранения. Другое содержимое с тем же ID отклоняется. Ожидающая или выполняющаяся операция не создаёт второго подтверждения; проверяйте её статус. Для повторной попытки после отказа, конфликта или ошибки используйте новый ID и новое подтверждение. После перезапуска незавершённые операции становятся `interrupted`.

Откат восстанавливает прежние версии и может удалить записи, созданные отменяемой MCP-операцией, включая её ручные копии внешних карточек. Он блокируется при изменении карточек, посторонних структурных ссылках, избранном и активном использовании медиа или столкновением. Группа откатывается целиком. Аудиофайлы не удаляются; регистрации аудио остаются для повторного использования. Тексты заметок при проверке ссылок не сканируются.

Общего инструмента удаления нет. Повторный откат одной операции и откат операции отката недоступны. История хранится локально в SQLite без автоматической очистки и без токенов подключения. UI обновляется после успешной записи на диск, открытые несохранённые черновики сохраняются.

Поддерживаются текущая ревизия MCP и sessionful Streamable HTTP для клиентов 2025 года. Неактивные сессии освобождаются через 15 минут; при заполнении лимита освобождается самая старая свободная сессия. Сервер слушает только loopback и не публикуется через туннель Owlbear.
